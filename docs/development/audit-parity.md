The Python implementation is a behavioral reference, not an infallible authorization oracle. Corrected semantics must be recorded and verified against Vault rather than preserving known false positives or false negatives. Existing request-audit logs and live management views remain separate.

Relationship checks currently follow the Python declaration-based grant model. They do not establish effective Vault authorization across competing ACL patterns, parameter constraints, required sudo, or successful authentication. Cross-block precedence and constrained-operation validation remain required before treating a reported chain as an executable escalation.

AppRole association collection reads RoleID endpoints and the entity-alias catalog, persisting only SHA-256 RoleID/alias-name hashes plus canonical entity IDs and auth mount accessors. Existing snapshots without these fields can only support inferred authentication steps. Full alias display/export remains pending.

REF-001 aggregates explicit, implicit-default and token allowed-policy references. It ignores allowed globs and disallowed policies, uses configured privileged-name patterns for severity, and suppresses absence findings when policy collection is incomplete. The built-in YAML limits REF-001 to AppRole/JWT/Kubernetes, as in the reference catalog; custom rules can reuse the detector for token roles. Native collection omits the synthetic root policy document, so the engine explicitly includes root in its known catalog.

Engine 9 derives Identity assignments separately from raw resources. New scans persist this analysis with the snapshot; offline analyze recomputes it and includes it in CLI JSON. The UI has a searchable assignment table with subject, policy, direct/inherited relationship and source group. Diamond inheritance is deduplicated by source group; cycles terminate and are reported as analysis gaps. Group policy inheritance is not automatically attributed to auth roles. Native tests cover nested groups, diamond paths, provenance, missing groups/entities and cycles; Acyclic inheritance matches Python on 8 fixtures covering both edge representations, diamonds and missing parents. Browser verification confirmed direct and inherited assignments with source group paths. The assignment table supports loading additional batches of 100 rows; large-table pagination still needs browser verification.

Offline comparison: `npm run audit -- diff OLD_RUN_ID NEW_RUN_ID` uses the selected SQLite database and VAULT_ADDR without a Vault token or network request. It rejects different targets, schemas, configuration fingerprints and engine versions. Exit codes are 0 for no added/changed high findings, 1 for added/changed high or critical findings, 2 for errors or incomplete analysis. Removed findings are labeled removed rather than resolved, with an explicit warning for collection/analysis gaps. Severity changes are retained even when evidence is identical (the Python fingerprint-only comparison can miss these). CLI smoke verification used two synthetic SQLite runs and confirmed exit 1 for a new high REF-001 finding.

The admin-authenticated GET /security-audit/diff endpoint uses the same compareRuns engine and target-scoped store lookups as the CLI. The web panel selects an old run, displays category counts, filters changes and expands before/after JSON. Browser verification on two synthetic runs showed one resource change and three added findings, with expanded evidence and Identity source-group provenance.

Baseline CLI: `npm run audit -- baseline-create RUN_ID FILE` writes a new 0600 JSON file (also valid YAML), refusing to overwrite an existing file. `scan --baseline FILE` and `analyze RUN_ID --baseline FILE` retain all findings and return separate fingerprint/status/gate records; known findings do not fail the severity gate. Collection/analysis gaps still return exit 2. Baselines require matching target, rule configuration fingerprint and engine version. Native fingerprints are versioned through the engine contract and are not claimed to match Python fingerprints. Missing baseline fingerprints are labeled absent, not verified remediated. Synthetic CLI verification confirmed high findings remain visible while a matching baseline produces exit 0 without a Vault token.

CLI `scan` and `analyze` accept `--exceptions FILE` using the Python YAML fields version/exceptions, id, rule_id, namespace, object_path, optional policy_path, owner, reason and expires. Expiry uses the local calendar date and remains active through the specified day. Rule IDs are exact; namespace/object/policy patterns use glob matching. Current native snapshots cover root only. Suppressed findings remain in the output with gate=false and full exception details; expired and unused entries are reported. Tests cover expiry boundary, path mismatch, invalid dates, duplicate IDs, unknown rules and required ownership. Controls UI, persistent revisions and cross-language controls fixtures remain pending.

CI arguments are now parsed strictly: unknown, repeated, missing-value, unsupported-command and conflicting options fail with exit 2. `scan`, `analyze` and `diff` accept `--fail-on none|critical|high|medium|low|info` (native default high), `--require-complete` (native default) and explicit `--allow-incomplete`. Findings at or above the threshold return 1; required completeness failures return 2; otherwise 0. These preserve the native CLI defaults/exit contract rather than the Python default none/exit-2 severity convention. Historical analyze validates exception rule IDs against the pinned catalog when available.

Offline exports: `npm run audit -- export RUN_ID FILE --format json|jsonl|yaml|csv`. Files are created with mode 0600 and exclusive creation. JSON/YAML preserve the stored detail, JSONL emits typed metadata/resources/findings/gaps/Identity assignments, and CSV exports findings with quoted cells and spreadsheet formula neutralization. These are native formats, not a claim of compatibility with the Python per-object YAML report tree and indexes. Export UI is implemented; Python report-layout parity remains pending.

The run page now offers report format selection and authenticated report download. API checks against the local synthetic database verified all four formats, three expected findings, attachment/no-store headers, HTTP 401 without authentication and HTTP 400 for unsupported formats. Browser inspection verified the controls and invoked JSON download without a page error; the browser-managed downloaded file was not independently inspected. Production build passed.

Collection now uses a shared serial request policy: default 10 requests/s, 3 retries, 500 ms exponential backoff capped at 10 seconds. Retryable HTTP statuses are 408/429/500/502/503/504; access errors and empty LIST responses are not retried. Existing VaultClient maps transport errors to 500. Snapshot collection metadata records parameters and request/retry/wait metrics. CLI scan accepts `--retries`, `--requests-per-second` and `--retry-backoff-ms`. Fake-clock tests verify spacing, eventual success, exhausted retries and immediate 403 failure. UI configuration, concurrent workers, total-duration bounds and live collector fault-injection coverage remain pending.

Collector parallelism: `scan --workers N` accepts 1..32 (default 10). Independent policy/Identity/role reads use a draining worker pool; discovery stages remain ordered. Every attempt passes a serialized admission queue for the shared rate limit, while network operations can overlap. Resources and issues are sorted before persistence. Local dev Vault comparison with workers=1 and workers=4 produced identical 12 resources, zero gaps and 13 requests. Tests verified peak concurrency and that active work settles before an error returns.

The run page exposes per-run workers, request rate, retries and initial backoff settings. POST /security-audit/runs validates numeric types/ranges and unknown fields before creating the run; the worker receives these validated options. Completed snapshot details display the recorded parameters and metrics. Unit validation and production build passed; the new settings form still requires browser end-to-end verification. Settings currently reset to defaults on page reload and are not a deployment-wide saved collection profile.

Duration limits: scan accepts `--timeout-ms` (default 30000) and `--max-duration-ms` (default 7200000), also exposed in the web collection form. The deadline AbortSignal cancels HTTP operations and rate/backoff timers; remaining reads do not start network requests. Already collected resources are returned with one collection/deadline gap and policiesComplete=false. A local raw HTTP fixture (supporting Vault LIST) stalled a policy read: the 200 ms deadline canceled it, retained the previously read policy and produced exactly one deadline gap. Unit tests and production build passed. The new duration controls still require browser verification.

`collect` now persists a read-only configuration snapshot with analysisPerformed=false and a distinct collected status, without running rules. It accepts collection/concurrency/deadline options and completeness controls. The UI explicitly labels the missing analysis, exports allow collected snapshots, and baseline/finding diff reject them. `analyze RUN_ID` evaluates the saved resources offline with the current configuration when no prior analysis is pinned. A temporary SQLite workflow against local dev Vault verified collect, stored status and offline analyze after removing VAULT_TOKEN; analysis produced expected POL-003 findings. Offline analyze prints by default; --save now persists a separate analyzed run.

Saved reanalysis: `analyze RUN_ID --save` persists a new result and records sourceRunId, retaining original collection timestamps and resources. `--current-rules` selects current rule settings; otherwise prior run settings remain pinned. The UI offers saved-snapshot analysis with current rules through the existing worker, without invoking collection. API checks source existence, finished state and target before creating the new run. A temporary SQLite CLI workflow without VAULT_TOKEN verified a separate completed result, unchanged collected source and retained collection timestamps. Browser/API end-to-end verification of the new reanalysis button remains pending; baseline/exception metadata is now persisted with CLI saved analyses.

Historical controls are shown as saved-date evidence; UI upload/edit/application implemented; browser validation pending. JSON/YAML preserve controls, JSONL metadata includes them, and CSV adds baseline_status/suppressed/gate/exception_id. Object limits: `--max-objects N` and the web form count retained policies and subjects (roles/entities/groups/aliases), excluding mount metadata; 0 means unlimited. On the next object beyond the limit, active/queued requests are canceled and one collection/object-limit issue marks the saved snapshot incomplete. Native collection omits the synthetic root policy document. Diff rejects runs with different object limits. Local dev Vault verification with four workers and limit 2 retained exactly two counted objects and one limit gap, without mislabeling it as a deadline. Tests and production build passed; UI control browser verification remains pending.

Collection scope: CLI collect/scan accepts repeatable glob flags `--policy-filter`, `--auth-mount-filter` (mount without trailing slash), `--auth-type-filter`, plus `--skip-identity`. The collection API accepts arrays (up to 100 patterns) and a boolean skipIdentity. Scope is pinned in snapshot metadata and checked by diff; auth mount metadata remains available for Identity correlation even if role reads are filtered. Filtered policy catalogs disable absence checks; skipped Identity is an explicit analysis gap. Local dev Vault verification confirmed policy/auth-type filtering and no Identity resources or false REF-001 results. Repeatable CLI filters and web scope controls are implemented; browser verification remains pending.

Namespace collection: collect/scan accept `--namespace PATH`, falling back to VAULT_NAMESPACE when no explicit flag is provided; the web form has a namespace field. Requests send X-Vault-Namespace, resources retain namespace, and policy coverage is stored per namespace. Paths normalize boundary slashes and reject control characters, empty internal segments and dot traversal. A local raw HTTP fixture verified the header on every request and namespace/coverage metadata. This is transport verification, not an Enterprise Vault integration test. Recursive namespace discovery and scoped UI authentication remain to be addressed; existing server authentication still follows upstream VaultLens behavior.

Namespace isolation applies before resolution, so an equal entity ID or accessor from another namespace cannot satisfy a reference. Tests cover resolved, missing, malformed and cross-namespace references, preserving raw resources. All 34 native tests and server type compilation passed.
